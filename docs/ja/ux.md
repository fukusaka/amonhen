# UI / UX の再検討

[English](../ux.md)

`docs/design.md` の「画面構成」を土台に、日常の操作を SourceTree・Fork・Tower・JetBrains（IDE の Git）と同じかそれ以上に楽にするための見直し。速度の方針（UI スレッドで git を待たない、1 フレーム以内）は変えない。

## 原則

| 原則 | 内容 |
| --- | --- |
| 速さを削らない | 新しい画面も「見えている分だけ計算・描画」。重いもの（複数コミットの差分、AI、GitHub）は後追いで足し、先に出せるものを先に出す |
| macOS の作法に従う | ウィンドウのタブ、Settings（⌘,）、ツールバーのカスタマイズ、メニューの網羅、macOS 標準のショートカットは崩さない。独自の作法は History と差分のような自前の画面の中だけ |
| 1 つの操作は 1 か所で完結 | 選ぶ → 確かめる → 実行 を同じ画面で。別ウィンドウ・シートは確認が要る操作だけ |
| すべて Undo できる | 書き込み系は操作ログ（oplog）に積み、ツールバーと Activity から戻せる |
| キーボードで全部できる | すべての操作にメニュー項目を持たせ、ショートカットはメニューから引く |
| 外部との通信は明示 | AI・GitHub は設定で有効にしたときだけ。送る内容を見せてから送る |

## 全体のレイアウト

```
┌ タブ: amonhen-standalone │ linux │ vscode-amonhen │ + ─────────────────────────────────────────┐
│ [◧] main ↑2↓0 │ Fetch Pull Push │ Branch Merge Rebase │ Stash Pop │  ⟳ 2 ops  ↶  🔍____ │
├────────────┬──────────────────────────────────────────────────────────────────────────────┤
│ WORKSPACE  │ （Working Copy / History / Conflicts / Stashes / Reflog のどれか）            │
│  Changes 5 │                                                                              │
│  History   │                                                                              │
│  Conflicts │                                                                              │
│  Stashes 2 │                                                                              │
│  Reflog    │                                                                              │
│ BRANCHES   │                                                                              │
│ REMOTES    │                                                                              │
│ PULL REQS  │                                                                              │
│ TAGS       │                                                                              │
│ SUBMODULES │                                                                              │
│ WORKTREES  │                                                                              │
└────────────┴──────────────────────────────────────────────────────────────────────────────┘
 merge・rebase・cherry-pick の途中は、ツールバーの下に帯: 「Rebase 3/7 · 2 件のコンフリクト  [Continue] [Skip] [Abort]」
```

- Conflicts はコンフリクトがあるときだけサイドバーに出し、件数を付ける。
- サイドバーの上の絞り込みの欄（Navigate > Filter Branches…、⌥⌘F）は、打った語をすべて含む名前だけに Branches・
  Remotes・Tags を絞る。合ったものは名前のまま平らに並べる。Esc で消す。
- ブランチ・タグは複数選べる（⌘ クリック、⇧ クリック）。History はそのどれかから辿れるコミットを出し、右クリックの
  メニューで名前をまとめてコピー、ローカルブランチだけならまとめてお気に入り・アーカイブ・削除ができる（削除は名前を並べて確かめる）。
  タグだけなら、下のタグの操作をまとめてできる。
- タグには、ブランチと違ってリモートの写しが手元にない（fetch したタグは手元の `refs/tags` に混ざる）ので、どの
  リモートにどのタグがあるかは手元の ref からは分からない。そこで Fetch（自動の fetch も）のついでに、各リモートの
  タグ（`git ls-remote --tags`）を読んで `<共通の git dir>/amonhen/remote-tags.json` に覚える。タグを push・削除
  したら、その場で覚えを直す。比べるのは ref が指すオブジェクトなので、同じコミットに作り直した注釈付きのタグは
  別のタグ（Push は断られる）。タグの行の右端には、どのリモートにもないとき（斜線の雲）と、リモートに同じ名前の別の
  タグがあるとき（橙）に印を出す。ツールチップにはリモートごとの様子（ある・別のタグ・ない・まだ確かめていない）を
  並べ、印を押すと、同じことと各リモートを読んだ時刻、Push・置き換えのボタンの吹き出しを出す。
- 署名付きのタグの行には、署名の印も出す（コミットの署名と同じアイコンと色。リモートの印の前、言葉はツールチップ）。
  確かめるのは見えているタグだけで、スクロールが止まってから。
- タグの右クリックは、分かっていることに合わせる: ないリモートへの Push <タグ> to <リモート>、同じ名前の別の
  タグがあるリモートでの置き換え…（強制の push）、手元のものだけを消す削除…（Undo できる。注釈付きのタグはメッセージごと
  戻る）、あるリモートからの「<リモート> から削除…」（ほかの人からも消え、Undo できない）。まだ読んでいないリモート
  には Push と削除を出し、シートで確かめていないと断る。削除と置き換えは、タグの名前を並べて先に確かめる。
- Workspace には、メインの画面を切り替える行を置く。Stashes は History（と Conflicts）の下に、stash があるときだけ
  件数付きで出し、選ぶと Stashes の画面（5a 節）を開く。stash そのものはサイドバーではなく、その画面に並べる。
  Reflog はいつも最後に出し、選ぶと Reflog の画面（5b 節）を開く。
- Pull Requests・Worktrees は該当するものがあるときだけ出す。

## 1. 複数のリポジトリ: タブと別ウィンドウ

参考: Fork（リポジトリごとのタブ）、Tower（ウィンドウのタブ）。

- `NSWindow.tabbingMode = .preferred` で macOS 標準のウィンドウのタブにする。タブのドラッグで別ウィンドウにでき、Window メニューの「すべてのウィンドウを結合」も標準で動く。自前のタブバーは作らない。
- ⌘T・タブバーの「+」: リポジトリの一覧を出し、選んだものを前のウィンドウのタブで開く（Quick Open ができたらそれに替える）。⌘N は新しいウィンドウ。Open… や一覧から開いたものも、前のウィンドウのタブに入れる。タブの切り替えは ⌃Tab・⌃⇧Tab と ⌘⇧] ⌘⇧[。
- **起動したとき**は、終了したときに開いていたウィンドウとタブを、同じ並びで開き直す。引数で渡したリポジトリや、Finder・`amonhen` から開いたものは、その後で前のウィンドウのタブに開く。終了する前に閉じたウィンドウは開き直さない（macOS のふつうの動き）ので、何も開いていない状態で終了すると、次はリポジトリのページが出る。フォルダがなくなったリポジトリは除く。
- **Dock のアイコンをクリック**したとき、見えているウィンドウがなければ、しまってある（最小化した）ウィンドウを戻し、それもなければリポジトリのページを新しいウィンドウに出す（最後のウィンドウを閉じてもアプリは終わらない。終えるのは ⌘Q）。
- **つなぐ必要のあるリポジトリ**（SSH 先、daemon 越し）は、開くとすぐにそのタブを置く（リポジトリが入る場所: 前のウィンドウのタブ、新しいウィンドウ、置き換えるタブ）。タブには接続中であることと「キャンセル」を出す。つながったら、リポジトリがそのタブに替わる。前に出すのはそのタブが前にあったときだけ（裏で終わったタブにフォーカスを取られない）。つなげなかったら、警告ではなく、タブを残してエラーと「もう一度」「タブを閉じる」を出す。起動時の復元・一覧から開く・「つなぎ直す」のどれもこうするので、タブとウィンドウの並びがつながった順に左右されず、つなげなかったリポジトリも、そのタブを閉じるまでは次の起動で開き直す。手元のリポジトリが起動時に開けなかったときも、エラーを出したタブを残す。
- 裏のタブはメモリを絞る: History のチャンクを見えている付近だけ残し（済みの仕組みを使う）、ファイル監視は続けるが status の再計算は前に出たときまで遅らせる。タブのタイトルに未コミットの変更の有無（●）と ahead/behind を出す。

## 2. ブックマーク（リポジトリの一覧）

今の「Repositories…」（開いた順の一覧）を、Fork の Repository Manager・SourceTree のブックマークに相当するものに広げる。

| 要素 | 内容 |
| --- | --- |
| 個別登録 | 「追加…」でフォルダを選ぶ・Finder からドロップ・開いたリポジトリを自動で追加（設定で切れる）。SSH 先（`ssh://`）もここに |
| フォルダから自動取得 | 「スキャンするフォルダ」を複数登録（例 `~/prj`）。深さ（既定 3）・除外パターン（`node_modules` など）を指定。見つけたリポジトリはそのフォルダ名のグループに入る。フォルダは FSEvents で見張り、増減を反映する。消えたものは灰色にして残し、手で外す |
| グループ | 手動のグループ（フォルダのような入れ子）と、スキャンのグループ。ドラッグで並べ替え・移動 |
| 状態 | 各行に今のブランチ・ahead/behind・変更のあるファイルの数。`.git/HEAD` だけは即読み、ほかは見えている行だけ裏で `git status --porcelain=v2 --branch --untracked-files=no`（ロックを取らない）を 4 つずつ。untracked は数えない |
| 付加情報 | 色ラベル、お気に入り（★）、表示名の上書き、最終オープン日時 |
| 操作 | 開く（⏎ 今のウィンドウのタブ、⌘⏎ 新しいウィンドウ）、Finder で表示、ターミナルで開く、エディタで開く、Fetch（選んだもの全部を一括で） |
| Quick Open | ⌘⇧O で全ブックマークをあいまい検索するパネル（Spotlight 風） |

一覧は 2 か所に出し、中身と操作は同じ（`RepositoryBrowser`）。

- **リポジトリのページ**: リポジトリを開いていないタブ（`RepositoryHome.swift`）。⌘T・⌘N・⌘O・⌘⇧R で出し、起動したとき・
  最後のリポジトリを閉じたときに何も開いていなければ出す。左に分類（すべて・お気に入り・場所（このMac と SSH のホスト
  ごと）・手で作ったグループ（作ってから出す）。それぞれ件数付き）。場所の下には、スキャンするフォルダ（🔍。探すのはここだけで、そのマシンの
  上で探す。SSH のホストは、そこのエンジンが `amonhen find-repositories` で探す）と、それ以外のリポジトリ（開いた・手で
  入れたもの）のフォルダが、リポジトリのあるフォルダの木（枝分かれもリポジトリもない途中のフォルダは `~/prj/oss` のように
  1 つにまとめる）で並び、フォルダを選ぶとその下のリポジトリを出す（場所の下のフォルダは、🔍 の外のものだけ。同じリポジトリを 2 か所で数えない。省いた名前はツールチップにフルパス）。加えるのは左の下の「＋」か右クリック: 場所なら手元の
  リポジトリ・SSH 接続・この Mac でスキャンするフォルダ・SSH 先でスキャンするフォルダ（まだ一覧にないホストでもよい）、このMac なら手元のリポジトリ・スキャンするフォルダ、ホストならそのホストのリポジトリ・スキャンする
  フォルダ、グループならグループ（SSH 先は、ホストを `~/.ssh/config` と `~/.ssh/known_hosts` から候補に出し、ホストの上のフォルダを
  読んで選べる。ダブルクリックで中に入り、リポジトリは緑。パスワードを聞かれるホストは読めないので、パスを入れる）。🔍 のフォルダでは、探す深さ・探し直す・スキャンをやめる。右に、選んだ分類の中のリポジトリを 1 回ずつ、
  並べ替えられる 5 つの列で出す: 名前とパス、ブランチ、状態（「変更 n」・上流との差 ↑↓・変更なしは ✓。列の見出しのツールチップに説明。SSH 先は開くまで読まないので「SSH」）、
  最後のコミット（いつ・件名）、最後に開いた日時（既定の並び。開いていなければ —）。行をお気に入り・グループにドラッグすると入れられる。
  選ぶ（ダブルクリックか ⏎）とこのタブがそのリポジトリになる（⌘⏎ で新しいウィンドウ）。右は絞り込みと一覧だけで、
  下にボタンは置かない。人が一度に把握できるのは 5〜6 個なので、
  ページのどの部分もその数に収める。ページにもリポジトリのタブと同じツールバーを付ける（リポジトリへの操作は押せない）
  ので、タブを切り替えてもタブの並びの位置が動かない。別ウィンドウは持たない。
- **ツールバーの左の Repositories**: リポジトリのページに切り替える（⌘⇧R）。
- **その隣のリポジトリ名**（GitHub Desktop と同じ）: 押すと一覧を名前と状態だけで出し（お気に入り、そのあと最後に
  開いた順）、選ぶと今のタブをそのリポジトリに切り替える。

保存は UserDefaults ではなく `~/Library/Application Support/Amon Hen/bookmarks.json`（構造があり、手で直せるように）。スキャンの結果は保存せず、起動時に裏で取り直す。

### SSH 先のホストごとの設定

SSH 先の設定は Settings… > SSH Hosts にある（3 章）。SSH 先の一覧と ＋／−、それぞれの接続・エンジン・署名の検証・探すフォルダ・そこにあるすべてのリポジトリに効く git の設定。Places の SSH 先の項目（右クリックの「設定…」）と、リポジトリの Settings の一覧の下の 1 行（`git 2.34 · build-1`）は、そのタブをその SSH 先で開く。Places の SSH 先の下の探すフォルダと、タブの探すフォルダは 1 つの設定。

## 3. 設定画面（Settings…、⌘,）

macOS 標準の、上にアイコン付きのタブが並ぶ形（`NSTabViewController` の `.toolbar` スタイル、中身は SwiftUI の `Form`）。大きさを変えられ、既定の幅は 960。大きさはタブを切り替えても起動し直しても保ち、タブの中身は窓いっぱいに広がる（長ければ中でスクロール）。今アプリメニューにあるトグルはここへ移す。

Settings… に置くのは、Amon Hen 自身が決めることと、機械ごとの git の設定（Git タブ）。1 つのリポジトリの git の設定はそのリポジトリの画面（4 章）にあり、Git タブはその行の「すべてのリポジトリ」の段で、この Mac と SSH 先のホストごとにある。どのタブにも共通の決まり: スクロールなしで 1 画面に収まる。折りたたまない（「詳細」は置かない）。説明は問いだけで分からない行にだけ数語、残りは ⓘ に。エディタは埋め込まない（テンプレートの本文、プロンプトはシートで開く）。プログラムはほかと同じく選び、書かせない。

| タブ | 項目 |
| --- | --- |
| General | 起動時に前回のリポジトリを開く、開いたリポジトリをブックマークに足す、リポジトリを開く既定（タブ / ウィンドウ）、自動で fetch（開いているすべてのリポジトリに 1 つの間隔）、外部エディタ（済み: 自動は入っているコードエディタの最初のもの、なければ既定のテキストエディタ。任意のアプリも選べる）・ターミナル・差分ツールの選択 |
| Git | 機械ごとの git の設定。リポジトリの設定の画面（4 章）を「すべてのリポジトリ」の段で開いたもので、同じページの一覧と同じ行を持ち、その機械の `--global` に書く。ページは、作者と署名、コミット（テンプレートの選択と、その下に共有のテンプレートの一覧。名前と ＋／−、本文はシートで「編集…」）、操作、Working Copy（リポジトリの exclude の代わりに「どこでも無視する」`core.excludesFile`）、プログラム（git・gpg・ssh-keygen・gpgsm を同じ形で選ぶ。「自動」は PATH の先頭で、出どころと版を添える。見つかったものは Homebrew 2.56.0・Apple 2.54.0 のように。「その他…」でパス。git はその機械の Amon Hen の設定 `~/.config/amonhen/settings.json` に置き、そこの CLI・共有の daemon・VSCode 拡張も従う。選んだ git がなければ行の下に出し、別の git で動かさずに git を動かす操作を止める。SSH 先のプログラムのページは、SSH 先のファイルに書く。ほかは `gpg.program`・`gpg.ssh.program`・`gpg.x509.program` に書く）、環境変数（この Mac で git と ssh に渡すもの。ログインシェルのものを使うか（端末が開くときと同じ形で読む）と、読んだ時刻・読み直す・SSH の agent の有無。変数を値と並べた表で、git と ssh がいつも使うものはチェックが入って外せず、ほかはチェックすれば渡し（`AMONHEN_PASS_ENV`）、渡せないものは理由を出す。その下に選んだ値の全体を、PATH のようなものは 1 か所ずつ、使われる git の場所を添えて。名前が秘密らしい変数の値は、表でも、その下でも「表示」を押すまで伏せ、検索では名前だけを見る。名前を英字と数字以外で語に区切り、TOKEN・SECRET・PASSWORD・PASSWD・CREDENTIAL・PRIVATE を含む語、AUTH か PASS そのものの語、KEY で終わる語（APIKEY も）があれば秘密らしいとする。ただし `SSH_AUTH_SOCK` と `AMONHEN_PASS_ENV` は除く。変えるとすぐ効き、共有の daemon にも届く。git の設定ではなく Amon Hen の設定）、キーと値。リポジトリにしかないページ（ブランチ、リモート、Hooks・LFS）は出ない。各行の設定元は「git の既定」か「すべてのリポジトリ」で、↩︎ と ⓘ はリポジトリのページと同じ。内部では、この段のためにアプリが持つ空のリポジトリを握り、その local の値は見ない |
| SSH Hosts | Amon Hen が知っている SSH 先の一覧と、＋／−（`~/.ssh/config` と known_hosts から選ぶか名前を書いて加える、忘れる）。選んだ SSH 先のページを 2 つ目の一覧に: 接続（ホスト、状態と接続の確認、エンジン、署名の検証、探すフォルダ）と、そこにあるすべてのリポジトリに効く Git のページ（SSH 先の `--global` に書く）。3 列。下の「SSH Hosts」を見ること |
| Accounts | GitHub: History の CI の状態とアバター、読むブランチとコミット数、アバターの URL を 1 回だけ読む。後に GitHub・GitLab などのアカウント（後述）。トークンはキーチェーン |
| Appearance | テーマ（システム / ライト / ダーク）、差分とメッセージのフォントと大きさ、History の並び順・1 行表示・表示項目・アバター・祖先の強調、グラフの色 |
| Diff & Merge | unified / split の既定、空白の無視、前後の行数、折り返し、タブ幅、マージエディタの既定の並び（後述）、diff3、マージエディタを開いたときに間違えようのないコンフリクトを解く（済み） |
| Commit | 件名の文字数の目安（50 / 72）、Sign-off を付ける、Conventional Commits の補完、コミット後に push。行ができるまでは出さない。テンプレートの一覧は Git > コミットにある |
| AI | 使う AI（なし / Apple Intelligence（端末内）/ Claude Code / Codex。既定は、端末内のモデルが使えればそれ、なければ「なし」）、選んだ CLI の場所・版・ログインの状態（見つからなければ入れ方を案内）、モデル、翻訳先の言語、リポジトリごとに送らない設定。詳細で用途ごとのプロンプト（9 章） |
| Performance | commit-graph の自動書き出し、fsmonitor、共有の daemon で開く、永続キャッシュの場所と大きさ・消去、裏のタブの扱い |

「詳細」タブはない。その項目は Performance（daemon）と Git（シェルの環境変数）と SSH Hosts（署名の検証。SSH 先ごと）にある。最初の Git タブにあった 2 行は移さずになくす。pull の既定（Pull のシートは常に「git の設定に従う」を最初に選ぶ。取り込み方は git の設定で、リポジトリの「操作」のページで、このリポジトリかすべてのリポジトリに）と、ユーザー全体の `rebase.updateRefs`（「操作」の同じ行を、すべてのリポジトリに設定する）。

### SSH Hosts

SSH 先についてのすべてを 1 か所に。SSH 先は機械なので、ここで決めたことはそこにあるすべてのリポジトリに効き、リポジトリの画面（4 章）には何も置かない。3 列にする。SSH 先の一覧、選んだ SSH 先のページの一覧、選んだページ。1 ページの中身は Settings… > Git の 1 ページと同じ量なので、窮屈にならない:

```
Settings… > SSH Hosts                          （幅 960: 150 / 170 / 640）

┌───────────┬──────────────┬──────────────────────────────────────────────┐
│ build-1   │ 接続         │ 接続                                         │
│ dev-2     │ 作者と署名   │   ホスト   build-1   ~/.ssh/config から      │
│ old-box · │ コミット     │   状態     ● つながっている                  │
│  つながら │ 操作         │            amonhen 0.2.7（送り込んだもの）   │
│  ない     │ Working Copy │            · git 2.34   [接続を確認]         │
│           │ プログラム   │                                              │
│           │ キーと値     │ エンジン                                     │
│           │              │   使うエンジン ( 自動                    ⌄ ) │
│           │              │   合うものがなければ送り込む         (●)     │
│           │              │   使っているもの ~/.local/share/amonhen/…    │
│           │              │ 署名の検証                                   │
│           │              │   検証に使う鍵  ( この Mac の鍵          ⌄ ) │
│           │              │                                              │
│           │              │ 探すフォルダ                                 │
│           │              │   ~/src    3 段まで                          │
│ [+] [−]   │ git 2.34 ·   │   ~/work   3 段まで                 [+] [−]  │
│           │   build-1    │                                              │

- **SSH 先の一覧**（左）。Amon Hen が知っている SSH 先すべて。Repositories の画面の Places にあるもの（そこのリポジトリか探すフォルダ）と、リポジトリを開いたことのあるもの。＋ は `~/.ssh/config` と known_hosts から選ぶか名前を書いて加える。− は忘れる。探すフォルダと、そこのリポジトリのブックマークも消える（確認を出す）。つながらない SSH 先も一覧に残り、薄い字で名前の後に「つながらない」と出る。
- **ページの一覧**（中）。先頭が「接続」、続いて Settings… > Git と同じページ: 作者と署名、コミット、操作、Working Copy、プログラム、環境変数、キーと値。一覧の下に、この SSH 先の git（`git 2.34 · build-1`）。リポジトリの Settings の一覧の下と同じ。
- **接続。** ssh が知っている名前、Amon Hen がつなげるか、そこで見つけたもの（エンジンと git）。「接続を確認」はもう一度試し、何で失敗したか（ssh、エンジン、git）を出す。エンジン: そこで動かす `amonhen`（自動＝SSH 先の PATH のものがこのビルドならそれ、なければ前に送ったもの、それもなければ送り込む。SSH 先の PATH のものだけ。Amon Hen が送り込むもの。SSH 先のパス）、合うものがなければ送り込むか、今使っているものとその用意のしかた。環境変数の `AMONHEN_REMOTE_ENGINE` と `AMONHEN_PUSH` はこれより優先し、あればページにそう出す。変えるとタブはつなぎ直す。もう開いている SSH 先のリポジトリは、開き直すまで前のエンジンのまま。署名の検証: この Mac の鍵で（既定。Settings… にあった全 SSH 先共通の 1 つのスイッチを、これに置き換える）か、SSH 先の git と鍵で。探すフォルダ: Places のその SSH 先の下にあるものと同じ。2 つは 1 つの設定。
- **git のページ。** Settings… > Git のページを、この SSH 先について開いたもの。同じ行で、読み書きするのは SSH 先の `--global`。上に 1 行、そう書く（「build-1 のすべてのリポジトリに効きます（build-1 の ~/.gitconfig）。端末の git も同じ設定に従います。」）。名前・メール・署名と鍵（鍵は SSH 先で集める）、テンプレートのファイル、pull・fetch・rebase・merge、改行・実行の権限・全体の excludes、SSH 先のプログラム、キーと値。これには、エンジンをリポジトリなしで SSH 先で動かせることが要る。そうすれば、Settings… を開いただけで、SSH 先のリポジトリを開いていなくても届く。それまでは、どのリポジトリを通して読んでいるかをページに出す。
- **SSH 先のプログラム。** git はこの Mac と同じ形で選ぶ（自動、SSH 先で見つかったものと版、「その他…」は SSH 先のファイルを選ぶ。下の「SSH 先のパス」）。選んだ git は SSH 先の Amon Hen の設定（そこの `~/.config/amonhen/settings.json`）に書き、SSH 先のエンジン・CLI・VSCode 拡張が従う。つなぎ直さずに次の操作から効く。選んだ git がなければ行の下に出し、接続のページにも「PATH の git に戻す」と出す。前の版でアプリが持っていた SSH 先の git は、Settings > SSH ホストがつないだときに SSH 先のファイルへ移す（ファイルにもう git があれば、そちらを残す）。gpg・ssh-keygen・gpgsm は SSH 先の `gpg.*.program` に書く。
- **SSH 先のパス。** SSH 先のパスを聞くところ（プログラムやエンジンの「その他…」、探すフォルダの ＋、SSH 越しにリポジトリを加えるときの「選ぶ…」）では、SSH 先のフォルダを Finder のカラム表示のように `/` から今のフォルダ（今の値、なければホーム）まで列で並べるシートを出す。git のリポジトリには緑の印を付ける。キーは Finder と同じで、↑↓ で列の中を動き、→ で選んだフォルダに入り、← で上の列へ戻り、名前を打つとその行を選び、⏎ で選ぶ（プログラムを選ぶときにフォルダなら、その中に入る）。パスの欄で打っているときは、キーは欄のもの。Windows の SSH 先では、列はドライブ（`C:\`、または `\\server\share\`）から始まり、パスの区切りは `\`。ほかのドライブへは打ち込んで行く。上のパスの欄には打ち込める（`~` は SSH 先のホーム）。隠しファイルは切り替え（⇧⌘.）で出し、選べないもの（フォルダを選ぶときのファイル、プログラムを選ぶときの実行できないファイル）は薄く出す。フォルダは SSH 先のエンジンが読む（`listDirectory`）ので、まだつないでいなければ先につなぐ。つなげなければ、打ち込んだパスを選べる。Places から探すフォルダを加えるときは、シートで SSH 先も選べる。プログラムを選ぶときは、ホームのボタンの隣のメニューから、プログラムがよくあるフォルダ（`/usr/local/bin`・`~/.local/bin` など）へ行ける。
- **この Mac のパス。** この Mac のパスも、標準の「開く」パネルの代わりに同じシートで選ぶ（標準のパネルは `/usr/local/bin` のようなフォルダが見えず、リポジトリの見分けもつかなかった）: プログラムの「その他…」（ホームのボタンの隣のメニューに `/opt/homebrew/bin`・`/usr/local/bin` など）、外部エディタの「その他…」（アプリはそのアイコンで）、リポジトリの一覧の ＋ の「手元のリポジトリ…」（リポジトリは開かずに選び、⌘ クリックでいくつでも。メニューには探すフォルダ）、＋ の「スキャンするフォルダ…」、Clone の場所（「新規フォルダ…」つき）、メッセージのテンプレートのファイル（SSH 先のリポジトリなら SSH 先のもの）。この Mac のフォルダは、SSH 先のエンジンと同じやり方でコアが読む。
- **SSH 先の環境変数。** そこのエンジンは ssh で動かすコマンドから起動するので、ログインシェルでないシェルの環境になり、`~/.profile` などで設定した PATH や `GIT_*` がないことがある（この Mac で Finder から開いたアプリと同じ問題）。「ログインシェルの環境変数を使う」（SSH 先ごと、既定はオフ）で、エンジンを SSH 先のログインシェルの環境で起動し（tcsh・csh・fish も、そのログインシェルが読むファイルを読む）、PATH の amonhen もその PATH で探す。プロフィールが何かを表示しても、つながりは壊れない。その下に、SSH 先から読んだエンジンの環境（そこの git にそのまま渡る。渡すかどうかを選ぶ列はない）と、選んだ値の全体、PATH は場所ごとに使う git の印つきで。値の伏せ方はこの Mac のページと同じ。スイッチを変えるとつなぎ直す。
- **ほかからの入口。** Places の SSH 先の項目（右クリックの「設定…」）と、リポジトリの Settings の一覧の下の 1 行（`git 2.34 · build-1`）は、このタブをその SSH 先で開く。近道であって、別の画面ではない。Places の「この Mac」にも「設定…」があり、Settings… > Git を開く。

## 4. リポジトリの設定（サイドバーの Workspace の Settings、⌘;）

リポジトリ 1 つの画面で、サイドバーの Workspace の最後の行（Repository > Repository Settings、⌘; でも開く）。置くのは、このリポジトリに属していて、かつ「設定」であるものだけ。リポジトリに対する git 自身の設定と、Amon Hen がリポジトリごとに持つわずかなもの。ほかのリポジトリに及ぶものは置かず、リポジトリのファイルやリポジトリの一覧の属性も置かない（それぞれの居場所は 4.7）。

最初の版（タブのあるシート、U11）は、git の設定を git が持つ形のまま見せていた。2 つ目（最初の画面の版）もその形を引きずっていた。「詳細」に畳んだ行、正確に押さないと開かない矢印、端末でしか効かない設定、一覧の属性。この設計は、使う人と、各行が何をするかから始める。

### 4.1 原則

1. **何が起きるかの言葉で問う。** 行はふつうの言葉の質問（「pull のとき、どう取り込むか」）で、答えもふつうの言葉（「マージする」「rebase する」「fast-forward」）。git のキーと生の値は、求めたとき（ⓘ）と「すべての設定」にだけ出す。
2. **今どう動くかを、いつも 1 つの値で見せる。** 欄には効いている値を出す。どこにも書かれていなければ「未設定」ではなく、git の既定の動きを出す。横に値の設定元（git の既定、すべてのリポジトリ、このリポジトリ）を書く。
3. **変えることと、戻すことは別。** 値を選ぶと、このリポジトリに書く。↩︎ はこのリポジトリが上書きしている間だけ出て、押すと上書きが消える。メニューに「上の段のまま」は置かない。
4. **1 つの判断は 1 つの選択。** git の 2 つのキーで 1 つのことが決まるなら（署名するかと形式、pull の方式）、行は 1 つの選択にして、両方のキーを書く。
5. **書かせず、選ばせる。** 答えを並べられるなら（署名の鍵、テンプレート、使う git、リモート）、行は一覧から選ぶ。手で書くのは「その他…」の項目であって、行そのものではない。
6. **Amon Hen が従うものだけ。** Amon Hen 自身の操作が無視する git の設定（明示的に引数を渡しているため）は、この画面に置かず、「すべての設定」に残す。同じ値でも端末と Amon Hen で動きが違うなら、説明にそう書く。
7. **共有のものは共有の場所に。** 機械のすべてのリポジトリに効くもの（名前・メール・署名の鍵、使う git、gpg のプログラム、全体の excludes）は、その機械の設定で決める。この Mac なら Settings… > Git、SSH 先なら Settings… > SSH Hosts。アプリに効くもの（自動 fetch）は Settings… > General に、テンプレートの一覧は Settings… > Git > コミットに置く。この画面は、そうした値が効いているときに設定元を「すべてのリポジトリ」と示し、書くのはこのリポジトリの値だけ。
8. **「詳細」は置かない。** 行は、この画面に置く価値があるか、ないかのどちらか。畳んで隠すものはない。
9. **設定でないものは、設定の顔をしない。** 使っている git、既定のブランチ、hooks、LFS、worktree は「操作つきの情報」として「このリポジトリについて」に。リポジトリのファイル（`.gitignore`）は Working Copy でファイルとして編集する。
10. **説明は読める大きさで。** 各質問の下に 1 文、本文と同じ大きさの薄い字で、質問より少し内側に。小さな字は使わない。
11. **言葉を 1 つにする。** 表示の言語にすべての名前を揃える。ページの名前も。キー・値・ファイル名は git のつづりのまま。

### 4.2 行の形

選ぶ設定で、このリポジトリには何も書かれていない（全体の値か git の既定が効いている）とき:

```
pull のとき、どう取り込むか                      ( マージする          ⌄ )   git の既定  ⓘ
    マージは、両側に新しいコミットがあればマージコミットを作る。rebase は、自分のコミットを
    取ってきたコミットの上に載せ直す。fast-forward は、分かれていれば取り込まない。
```

同じ行で、ここで「rebase する」を選んだ後:

```
pull のとき、どう取り込むか                      ( rebase する         ⌄ ) ↩︎  このリポジトリ  ⓘ
    マージは、両側に新しいコミットがあればマージコミットを作る。…
```

ⓘ を押すと、どこに書かれているかが吹き出しに出る。行は開かない:

```
  pull.rebase = true
  このリポジトリ（.git/config）
  ここで上書きしなければ: マージする（すべてのリポジトリ、~/.gitconfig）
```

はい／いいえの設定は、同じ設定元つきのスイッチ:

```
rebase の前に変更を退避する                                   (  ●)   このリポジトリ  ↩︎  ⓘ
    コミットしていない変更を、rebase と rebase で取り込む pull の前に退避し、後で戻す。
    History の編集はいつも退避する。
```

答えを集めて並べる選択（署名の鍵。上で選んだ形式で一覧が変わる）:

```
鍵                                ( 0F8A 1B2C … Ada Lovelace <ada@example.com>  ⌄ )   すべてのリポジトリ  ⓘ
                                    ├ 0F8A 1B2C … Ada Lovelace <ada@example.com>
                                    ├ 7D3E 9A10 … Ada Lovelace (work) <ada@work.example>
                                    └ その他…
```

使っている git が従えない行（ここでは git 2.38 未満での積み重ねたブランチ）:

```
rebase のとき、積み重ねたブランチも一緒に動かす      ( 動かさない   ⌄ )   git の既定  ⓘ
    ⚠ git 2.38 以降が必要。このリポジトリの git は 2.34（build-1）。
```

左から順に: 質問とその下の説明、効いている値を出す欄、このリポジトリが上書きしている間の ↩︎、設定元、ⓘ。

### 4.3 値の設定元

| 設定元 | 意味 | git では |
| --- | --- | --- |
| git の既定 | どこにも書かれていない。git 自身の既定の動きを出している | — |
| すべてのリポジトリ | git を動かすユーザーが、すべてのリポジトリに決めた（この Mac なら Settings… > Git、SSH 先なら Settings… > SSH Hosts） | `--global`（`~/.gitconfig`） |
| このリポジトリ | ここで決めた。↩︎ で消せる | `--local`（`.git/config`） |
| この worktree | 今の worktree だけに決めた | `--worktree` |
| システム全体 | この機械のすべてのユーザーに決めてある（ここでは読むだけ） | `--system` |

SSH 先のリポジトリでは、「すべてのリポジトリ」は SSH 先のユーザーのもので、設定元もそう言う（「build-1 のすべてのリポジトリ」）。ツールチップにファイルを出す。git の scope を指す言葉はアプリ全体でこれだけにする。git config の表の「設定元」の列も同じ言葉で、「global」「local」「system」はその列のツールチップにしか出さない。

### 4.4 書くことと、戻すこと

- 値を選ぶと、すぐこのリポジトリに書く（`git config --local`）。確認は出さない。↩︎ が戻る道で、書けた時点で設定元が変わる。
- どのページの書き換えも、ページを出している間は 編集 > 取り消す（⌘Z）・やり直す（⇧⌘Z）で何段でも戻せる（Settings… > Git も同じ）。前の値に戻す（↩︎ は上の段の値にする）。リポジトリの操作の Undo（⌥⌘Z、コアの操作ログ）とは別の記録で、互いに戻し合わない。
- 書けなかったら、行の下に赤でその理由を出し、欄は前の値に戻る。
- この画面は `--global` には書かない。機械のすべてのリポジトリに効く値は Settings… > Git（この Mac）か Settings… > SSH Hosts（その SSH 先）で決め、どちらも「端末の git もこの設定に従う」と書く。ここでは、そうした値が効いていることを出どころで示すだけで、git config の段ごとの表の「すべてのリポジトリ」の列は読むだけ。（行の「すべてのリポジトリに設定」と、その列をここで編集することは、作ってみてやめた。同じものを 2 か所目に置くことになり、設定の行の右クリックは誰も探さないから。）

### 4.5 ページ

左に一覧、右に選んだページ（システム設定と同じ形）。一覧に組はない。よく変えるページを先に、たまに見る 2 つを最後に並べ、一覧の下に小さな 1 行で、このリポジトリを動かしている git を出す（`git 2.54.0 · この Mac`、`git 2.34 · build-1`）。押すと Settings… > Git がその機械を選んだ状態で開く（3 章）。ページの名前は中身で付ける。「〜について」「すべての〜」という名前は付けない。ここにあるものはどれも、このリポジトリの設定だから。

| ページ | 行 |
| --- | --- |
| 作者と署名 | **名前**、**メール**（`user.name`・`user.email`。一覧にできないので手で書く）。**署名**: 1 つの選択で、署名しない／OpenPGP／SSH／X.509（`commit.gpgsign` と `gpg.format` を一緒に書く）。**鍵**: 選んだ形式に合わせて集めた一覧（OpenPGP は `gpg --list-secret-keys` でメールアドレスの合う鍵を先頭に、SSH は `~/.ssh/*.pub` と `ssh-add -L`、X.509 は `gpgsm --list-secret-keys`）と、一覧にない値のための「その他…」。集めるのはコアなので、SSH 先のリポジトリなら SSH 先で集める（`user.signingkey`）。名前・メール・署名・鍵は、すべてのリポジトリの段の同じ行が Settings… > Git にあり、gpg・ssh-keygen・gpgsm のプログラムもそこで見つけて上書きできる。 |

### 4.6 古い git と SSH 先

- 使っている git が知らない設定の行は、隠さずに、選べない形で出す。要る版と、見つかった版（とホスト）を添える。隠さないのは、なぜその動きがないかを使う人が知るため。
- SSH 先では、どの行も SSH 先の git を読み書きし、一覧（署名の鍵、リモートに届くか）も SSH 先で集める。そこでの `--global` の値は、設定元に「<ホスト> のすべてのリポジトリ」と出す。

### 4.8 段階

画面の枠組み（一覧、行、設定元と ↩︎、Pull と Fetch が git の設定に従うこと）の後は、それぞれを別の PR にする。

1. 作者と署名を 1 つの選択にし、鍵をコアで集める。
2. Settings… のテンプレートの一覧（U21 の後は Git > コミット）と、そこから選ぶか専用に写すコミットのページ。
3. 操作を 1 ページに。Working Copy に exclude のエディタ。`.gitignore` を画面から外し、Working Copy に「.gitignore に追加」。
4. リモート: 接続の確認つきのシートと、サイドバーの右クリック。
5. Hooks・LFS を操作つきの表に。
6. キーと値（git config を Xcode の形の表に）。
7. SSH 先の設定: Settings… > SSH Hosts（3 章、U22）。エンジンをリポジトリなしで SSH 先で動かせるようにしてから。この Mac の設定は済み（Settings… > Git）。

参考: Fork（Fetch・Pull・Push・Stash・Pop の並び）、Tower（操作ごとのメニュー付きボタン）。

- 今のブランチに上流がない（そのリモートブランチが消えた）ときは、Push を Publish と見せ（ツールバー・Repository メニュー・Commit and Publish）、送り先のリモートを `branch.<name>.pushRemote`・`remote.pushDefault`・リモートが 1 つならそれ・origin の順で選んだ状態から選ばせ、そこでの名前も決めさせる。送ったものが上流になる。そのリモートブランチがもうあれば、そう伝えて代わりにそれを上流にする（ブランチにないコミットがあれば、先に Pull するよう伝える）。
- チェックアウトしていないローカルブランチは、右クリックで上流と合わせる（最後の Fetch の時点）: 上流より後ろにだけあれば Fast-Forward（checkout せずに進め、Undo に記録する。ほかの worktree でチェックアウト中のものは除き、その worktree を開く項目を出す）、先にだけあれば Push、上流がなければ Publish。分かれていれば checkout して merge か rebase をする。Fetch がひとりでにブランチを進めることはしない。
- Refresh は残す。変更は自動で検知するが、ネットワーク上のファイルシステム・SSH 先・ほかのツールが `.git` を直接書き換えたときなど、検知が漏れる場面で確実に揃えるため。押したら読み直しの間だけボタンを回す。
- `allowsUserCustomization = true` にして、Branch・Merge・Rebase・Cherry-pick・Terminal・Finder・GitHub で開く などを足し引きできるようにする。
- ahead/behind は Push・Pull のバッジ（macOS 26 以降）とブランチ名の横の両方に出す。
- 使えないときは無効にし、ツールチップに理由（「上流がありません」「コンフリクトの解決中です」）。
- ブランチの削除と stash の drop は先に確かめる（どちらも Undo で戻せる）。今のブランチにも上流にも取り込まれていないコミットがあるブランチは、それをシートに並べ、「それでも削除」（git の `-D`）で消す。
- Pull・Push・ブランチに ▾ のメニューは付けない。アイコンを 1 回押しただけで、外に送ったり履歴を書き換えたりしないこと。外に出る・ブランチが動く操作（Pull・Push・Pop・Undo）は、何が起きるかをシートで見せる。↩ で実行するので、キーボードからは 1 打増えるだけ。Fetch・Refresh はすぐ実行する（手元のものを変えない）。メニューのショートカット（⌃⌘L・⌃⌘P）も同じシートを出す。Commit and Push は重ねて聞かない。
- 同じものは 1 か所に: ツールバーに検索欄があれば History の中の検索欄は隠す（一致の件数・前・次・絞り込みは History に残す）。ツールバーに Branch があれば、ウィンドウのサブタイトルにブランチ名を出さない。
- ネットワークを使う git が 120 秒なにも出さなければ（ふつうは誰にも見えない認証の入力待ち）、そう書いたエラーで止める。Activity から取り消すこともできる。

## 5a. Stashes

stash は `refs/stash` とその reflog に置かれるコミット。中身は作業ツリーで、作ったときの HEAD（土台）と index を親に
もつ（`-u` なら untracked のファイルも）。一覧はすべての worktree で共有で、戻す先は書き込む先の worktree。

- サイドバーの Stashes（View > Stashes ⌘4）を選ぶと、この画面を開く。左に stash の一覧（新しい順）、右に選んだ
  stash の中身（History の詳細と同じ欄。土台は 1 つ目の親のリンク）。
- 各行は `stash@{n}` とメッセージ（メッセージなしで作ったものは WIP と土台の件名）、その下に作ったブランチ（今の
  ブランチでなければ薄く）、土台と書き込む先の worktree の HEAD の関係（HEAD と同じ・HEAD から N 個後ろ・橙で
  HEAD の履歴にない。履歴にないと戻すときに重なりやすい）、いつ、untracked のファイルを含むか、土台の短い ID。
- Apply・Pop・Drop…・Branch… は一覧の上と、各行の右クリック。Apply・Pop は、stage していた分をできれば stage
  したまま戻す（`--index`）。Drop は先に確かめ、Undo できる。Branch… は `git stash branch`: 土台にブランチを作って
  切り替え、そこに戻すので、HEAD がどれだけ進んでいても重ならない。worktree が 2 つ以上あれば、戻す先の
  worktree（✎）を帯に出す。
- 最後の stash を pop・drop したら、History に移る。

## 5b. Reflog

書き込む先の worktree の HEAD の reflog。HEAD が指してきたところを新しい順に並べる。reset・rebase・amend で外れて、
もうどのブランチからも辿れないコミットも入る。そういうコミットを見つけて取り戻すところ。

- サイドバーの Reflog（View > Reflog ⌘5）を選ぶと、この画面を開く。左に reflog の行、右に選んだ行のコミット
  （History の詳細と同じ欄）。
- 各行は `HEAD@{n}` と何をしたか（git のメッセージ: `commit: …`、`checkout: moving from a to b`、
  `reset: moving to …`）、その下に、どの ref からも辿れなければ橙で「どのブランチにもない」、いつ、短い ID、
  コミットの件名。
- New Branch… と Checkout（detached）は一覧の上。各行の右クリックには、ほかに New Tag、Reset ▸（5c 節）、History で
  見る（History にあるコミットだけ）、Copy Commit ID、Copy Name。worktree が 2 つ以上あれば、どの worktree の HEAD か（✎）を帯に出す。
- HEAD が動いたとき、書き込む先の worktree を変えたときに読み直す。

## 5c. Reset

History の行と Reflog の行の右クリックの「Reset <ブランチ> to <コミット> ▸」は、書き込む先の worktree の今のブランチ
（detached なら HEAD）をそのコミットに動かす（`git reset`）。先に、ブランチとコミットを書いて確かめる。

- Soft は外したコミットの変更を stage したまま残し、Mixed は stage せずに作業ツリーに残し、Hard は index と作業
  ツリーもそのコミットに合わせる。
- Hard は、コミットしていない変更を先に stash に残す（「Before reset --hard to …」。untracked のファイルは git と
  同じく触らない）ので、なにも失わない。
- どれも Undo（⌥⌘Z）できる: Soft と Mixed は同じ種類の reset で、Hard は `--keep` で戻す。外したコミットは Reflog
  から辿れる。merge・rebase・cherry-pick・revert の途中はできない。

│   ▣ M  src/main.rs           +5  −1    │  ← 一部の行だけ含める
│   ☐ M  README.md             +1  −1    │
│   ☐ ?  notes.txt                       │
└────────────────────────────────────────┘
```

### チェックボックスの 1 群

Staged / Unstaged の 2 群をやめ、変更のあるファイルを 1 つの一覧にして、各行のチェックボックスで「次のコミットに含めるか」を示す。チェックボックスは index（stage）の状態そのもので、FE だけの選択状態は持たない（ターミナルで `git add` してもそのまま反映される）。

| 状態 | 意味 | 押したとき |
| --- | --- | --- |
| ☑ | 作業ツリーの変更をすべて stage 済み | ファイルごと unstage |
| ▣ | 一部だけ stage 済み（行・hunk 単位で含めた） | すべて stage |
| ☐ | stage していない | すべて stage |

- 見出しの行（Changes）とディレクトリの行も 3 状態のチェックボックスで、配下をまとめて切り替える。
- 見出しに「全体の数 / 含める数」。Commit は含めるものがないと押せない（Amend を除く）。
- 新しいファイル（?）・削除・名前の変更も同じ扱い。コンフリクトのファイルはチェックボックスの代わりに ⚠ を出し、押すとマージエディタを開く。

- コミットの入力を上に置く（JetBrains・GitHub Desktop と同じく、「何を書くか」を先に見せる）。入力欄は畳める（件名の 1 行だけにする）。
- 一覧の見せ方を 3 つから選ぶ: List（パスを 1 列）、Tree（ディレクトリの木、1 つしか子がない段はまとめる。済み）、Flat（ファイル名と、薄い字で親ディレクトリ）。並び順はパス / 状態 / 拡張子。
- 絞り込み欄（パスのあいまい検索）。数百ファイル変わったときに効く。
- 各行に +/− の行数、状態のアイコン（M / A / D / R / ? / U）、行のホバーで Discard のボタン。Space で選んだファイル（複数可）のチェックを切り替え、⌫ で破棄（確認つき）。

### コミットを書きやすくする

| 機能 | 内容 |
| --- | --- |
| 文字数 | 件名の残りを表示し、50 で注意・72 で警告の色。本文は 72 桁の目安線 |
| 下書き | リポジトリごとに自動保存。コミットするまで消えない。`commit.template` があれば初期値に |
| 過去のメッセージ | 件名の欄で ⌥↑ / ⌥↓ で最近のメッセージを呼び出す。▾ で一覧 |
| 補完 | `Co-authored-by:`（過去の作者から）、`#123`（GitHub の issue）、Conventional Commits の型（`feat:` など）、ブランチ名に含まれる issue 番号 |
| Commit ▾ | Commit / Commit and Push / Amend / Amend（メッセージはそのまま）/ Fixup! 選んだコミット |
| Amend | オンにすると前のメッセージを入れ、差分の上に「HEAD との差」を出す。push 済みなら警告 |
| hooks | pre-commit などの出力は進捗をシートで見せ、失敗したら出力を残してメッセージは消さない |
| AI | 「メッセージを提案」（stage 済みの差分から）。後述 |
| 無効の理由 | Commit を押せないときは、ボタンの横に理由（「stage したファイルがありません」） |

### 右の差分で細かく stage する

参考: GitHub Desktop の行のガターのチェック、JetBrains の行ごとの含める・含めない。

一覧が 1 群になるので、差分も 1 本にする。右には HEAD → 作業ツリー の差分を出し、変わった行ごとに「次のコミットに含めるか」（index に入っているか）をガターのチェックで示す。

```
 ☑ ▾ @@ fn parse @@                         [Discard hunk]
     12   let a = 1;
 ☑ − 13   let b = 2;
 ☑ + 13   let b = 3;
 ☐ + 14   dbg!(b);          ← 作業ツリーにだけある行
```

- コアで HEAD → index と index → 作業ツリーの 2 つの差分を重ね、HEAD → 作業ツリーの各変更行に「stage 済みか」を付けて返す（`working_diff_combined`、行の `flags` の `STAGED`）。index が「HEAD に変更の一部を当てたもの」として表せないファイル（index にだけある変更が作業ツリーで書き戻されたなど）は、ファイルごと従来の Unstaged / Staged の切り替えで見せる。
- 切り替えは「HEAD にどの変更を当てたものを index にするか」を作り直して書く（`set_rows_staged`）。すべて含めるなら `git add`、すべて外すなら `git reset` と同じにする（新しいファイル・消したファイルのため）。
- hunk の見出しのチェックは 3 状態で、押すと hunk ごと含める・外す。
- 行のチェックを押すとその行を切り替える。ガターをドラッグで範囲、⌘ クリックで追加して選び、Space でまとめて切り替える。
- 変更のまとまり（連続する − と ＋）の境目をクリックすると、そのまとまりだけを選ぶ。
- キー: Space 選んだ行（なければ今の hunk）のチェックを切り替え、`D` 破棄、`J` / `K` で次・前の hunk、`⌥J` / `⌥K` で次・前のファイル。
- 切り替えた後は同じ位置に留まり、次の hunk にカーソルを移す（楽観的に表示を更新し、status の確定で合わせる）。
- 表示の切り替え（差分の上の帯）: unified / split、空白の無視、前後の行数（3 / 10 / 全部）、折り返し。
- Discard は oplog に内容を残し、Undo で戻せる（今の作業ツリーの内容を blob に書いておく）。

## 7. History の右の列

### メッセージを全文読める

- 16 行で畳むのをやめ、既定は全文。右の列は上（詳細）・中（変更ファイル）・下（差分）の境目をドラッグでき、位置を覚える。
- 詳細の欄の右上に「⤢」: 押すと詳細だけを右の列いっぱいに広げる（もう一度でもとに戻す）。
- 本文は選択・コピー・検索（⌘F が右の列にフォーカスがあるときはこの中を探す）ができる。

### GitHub の PR のような差分表示

今の「ファイルを選ぶと、その差分だけ出す」に加えて、「全ファイルを縦に連ねる」表示を選べるようにする。

```
┌ 変更ファイル（木）──┬ 差分（全ファイルを縦に）──────────────────────────────┐
│ ▾ src               │ ▾ src/lib.rs                      +12 −3  ☐ Viewed  ⋯ │ ← 見出しは上に張り付く
│    lib.rs   +12 −3  │   @@ fn main @@                                       │
│    main.rs  +1  −0  │   …                                                   │
│ ▾ docs              │ ▾ src/main.rs                     +1 −0   ☐ Viewed  ⋯ │
│    design.md +40    │   …                                                   │
│ 3 files +53 −3      │ ▸ Cargo.lock（生成物のため畳んでいます）  +210 −180   │
└─────────────────────┴───────────────────────────────────────────────────────┘
```

- 左の木で押したファイルへ飛ぶ。スクロールに合わせて木の選択が動く。
- ファイルごとに畳める。lockfile・`linguist-generated`・バイナリ・1000 行を超えるものは最初から畳む。
- 「Viewed」（見たもの）を付けると畳み、木に ✓。コミットごとに覚える（複数のコミットをまたいだレビューに使う）。
- 見出しの ⋯: blame、ファイルの履歴、このコミットの時点の内容を開く、エディタで開く。
- 仕組み: コアで全ファイルの差分を一度だけ取って持ち（`StackedDiff`、ファイルが多ければ並列に取る）、「ファイルの見出しの行（`DiffRow::FILE`）＋各ファイルの行」を 1 本につないだ表示を作る。文字列はファイルの中身を共有したまま。畳む・開くたびに表示だけを作り直す。差分表示の Metal の仕組みはそのまま使える。linux でコミットを選んでから差分が出るまでの時間は、1 ファイルずつのときと変わらない（p50 15〜16 ms）。
- 単体のファイル表示（今のもの）は残し、見出しの切り替えで選ぶ。

### 複数のコミットを選んだとき

| 選び方 | 見せるもの |
| --- | --- |
| 連続する範囲（⇧ クリック、1 本の first-parent の上） | 一番古いものの親から一番新しいものまでの差分（squash した結果と同じ）。上に「5 commits · 2 authors · 3 days · +120 −40」と、含むコミットの一覧（押すと単体に） |
| 2 つ（⌘ クリック） | 2 つの間の差分（A..B）。⇄ で向きを入れ替え、「merge-base から」（A...B）も選べる |
| 3 つ以上で飛び飛び | コミットごとの差分をファイル単位でまとめる（ファイルの見出しの下に、どのコミットの変更かを小見出しで） |

- 選んでいる間の右クリック: cherry-pick（並びを保って）、revert、squash（連続のとき）、ID をまとめてコピー、patch として保存。
- 範囲の端が merge をまたぐときは first-parent の範囲として扱い、そう書いて出す。
- 仕組み: コアの `Selection::of` が History のグラフで first-parent のつながりを調べ、`selection_diff` がバックエンドの `changes_between`（2 つのコミットの木の差分）で全ファイルの差分を作る。とびとびのときは、各コミットの差分を「パス — 短い ID」の見出しでパス順・古い順に並べる。

## 8. コンフリクトの解決（埋め込みのマージエディタ）

### 流れ

1. merge・rebase・cherry-pick・stash pop でコンフリクトが出たら、ツールバーの下に帯を出し、サイドバーの Conflicts を選んだ状態にする。
2. Conflicts の画面は「左: コンフリクトのファイルの一覧（未解決 / 解決済み）」「右: マージエディタ」。別ウィンドウにはせず、⤢ で切り出せるだけにする。
3. すべて解決したら帯の Continue が強調される。Continue は rebase なら次のコミットへ進み、新しいコンフリクトがあればそのまま次のファイルを開く。
4. 帯からいつでも Abort（oplog に残るので Undo でも戻せる）。

### エディタの並び（JetBrains に合わせる）

```
┌ Ours（main）─────────┬ Result ──────────────────┬ Theirs（feature）────┐
│                      │                          │                      │
│  変更 A   ≫ ✕ ───────┼──▶                       │                      │
│                      │      ◀──────────────────┼─ ✕ ≪   変更 B       │
│  衝突     ≫ ✕ ═══════╪══ ⚠ 衝突 ═══════════════╪═ ✕ ≪   衝突         │
└──────────────────────┴──────────────────────────┴──────────────────────┘
 ✨ Magic Merge   ← → 次・前の変更   Base を表示   Accept Ours / Accept Theirs   変更 4・衝突 1   [Save & Mark Resolved]
```

- 3 列の間を変更ごとの帯（曲線）でつなぎ、色で種類を示す: 追加は緑、変更は青、削除は灰、衝突は赤。
- 各変更に「≫ / ≪ 取り込む」「✕ 捨てる」。衝突は両方を取り込むと順に並ぶ（どちらを先にするかは ⌥ で）。
- Result は直接編集できる（`NSTextView`、日本語入力は OS 標準）。
- Base は既定では隠し、「Base を表示」で 4 列目（または Ours・Theirs の各列に Base との差として重ねる）。
- 今の「上に 3 ペイン・下に Result」の並びはやめ、3 列だけにする。3 列の縦のスクロールは揃え、変更の位置を合わせる（行数の差は帯で吸収する）。

### Magic Merge（自動で片づける）

JetBrains の「Apply non-conflicting changes」と「Resolve simple conflicts」に当たるもの。✨ を押すと次を順に適用し、適用したものは帯の色を薄くして残す（1 つずつ戻せる）。

1. 衝突しない変更（片方だけが変えたところ）をすべて取り込む。
2. 両方が同じ変更をしたところは 1 つにする。
3. 空白・改行コードだけが違う衝突は、設定の側（既定は Theirs の内容を Ours の空白で）にする。
4. 同じ行の中で別々の単語を変えた衝突は、単語単位で 3-way マージする（単語の境目は差分表示の単語差分と同じ）。
5. 片方が行を足しただけ（import の追加など）で並びが衝突したものは、両方を並べる（言語の文法が分かるときは tree-sitter で import・use の並びだと判定できたときだけ）。

- ファイルを開いたときに 1・2 だけは自動で適用する（設定で切れる）。残った衝突の数を一覧とタブに出す。
- 計算はすべてコア（`mergeSides`・`resolveText`・`conflictRegions` に足す）。単語単位のマージと判定はテストで固める。
- 一覧の右クリックで「このファイルは Ours / Theirs で解決」「外部のマージツールで開く」。
- Magic Merge の後に残った衝突は、AI で解消を提案できる（9 章）。エディタの下の帯の ✨ Magic Merge の隣に「AI で解消」。

## 9. AI（翻訳・解説・メッセージの提案・コンフリクトの解消）

| 場所 | ボタン | 動き |
| --- | --- | --- |
| History の詳細 | 翻訳 | 件名と本文を設定の言語に訳し、原文の下に折りたためる形で出す |
| History の詳細 | 解説 | コミットの差分とメッセージから「何をなぜ変えたか」「影響しそうな箇所」を要約。複数選んだときは範囲全体を |
| Working Copy | 提案 | stage 済みの差分からメッセージを提案（リポジトリの過去の書き方に合わせる） |
| 差分の hunk | 解説 | その hunk だけ |
| マージエディタ | 解消 | 衝突 1 つ・ファイルの残りの衝突すべて・全ファイルのどれかを対象に、解決案を作る（下の「コンフリクトの解消」） |
| マージエディタ | 解説 | 衝突 1 つについて、Ours と Theirs それぞれの意図（各側のコミットのメッセージと差分から）を説明する |

### コンフリクトの解消

- 順番は Magic Merge が先、AI は残った衝突だけ。機械的に決まるものを AI に渡さない（速く、間違いが入らない）。
- 送るもの: 衝突の Base・Ours・Theirs と前後の行、ファイルのパスと言語、両側で衝突に関わるコミットの件名と本文（merge なら `merge-base..` の各側、rebase なら当てているコミット）。
- 返させる形は決めておく（衝突ごとの解決後のテキストと、短い理由。JSON）。形が合わない・衝突の数が合わない返答は捨てて、エラーとして出す。
- 結果は Result に「提案」として入れ、紫の帯と理由の吹き出しで示す。衝突ごとに「採用」「却下」「編集して採用」。採用するまで解決済みにしない。一括採用はファイル単位で、確認つき。
- 採用した提案は oplog に残し、Undo で戻せる。
- 提案した内容にコンフリクトの印（`<<<<<<<` など）が残っていたら採用できなくする。言語が分かるときは tree-sitter で構文の壊れを確かめ、壊れていたら警告を出す。
- ファイル全体を送るのは、衝突がファイルの大部分を占めるときだけ。それ以外は衝突の前後に絞る。

- 接続先は手元の CLI で、Claude Code（`claude -p --output-format stream-json --verbose --include-partial-messages --tools "" --no-session-persistence`、空の一時ディレクトリで起動してリポジトリの CLAUDE.md を読ませない）か Codex（`codex exec --json --sandbox read-only --skip-git-repo-check -`）のどちらかを Settings > AI で明示的に選ぶ。見つかったものを勝手に使うことはせず、選ぶまで AI のボタンは出さない。用途ごとには分けず、全体で 1 つ。
- どちらも子プロセスとして起動し、プロンプトと差分は標準入力で渡して、流れてくる JSON を読む。鍵の管理はアプリで持たず、CLI のログインに任せる。
- Apple Intelligence（端末内。macOS 26 で Apple Intelligence を入にした Mac）は Foundation Models を直接使う。Mac の外に何も出ないので、リポジトリごとの確認はしない。一度に読めるのは約 4,000 トークンなので、いちばん長い変数（ふつうは差分）を詰める。翻訳や短い解説に向き、大きなコミットやコンフリクトの解消は Claude Code・Codex のほうがよい。
- モデルは CLI ごとに覚え、プルダウンで選ぶ（Claude Code は Haiku・Sonnet・Opus・Fable、Codex は `~/.codex/models_cache.json` に一覧で出ているもの。「その他…」で名前を書ける）。`--model`（Codex は `-m`）で渡す。Claude Code の既定は速い `claude-haiku-5-5`、解説だけ `claude-sonnet-5-5` を選べる。
- ツールを使わせない設定で起動する（Claude Code は使えるツールを空に、Codex は sandbox を読み取り専用に）。解説・翻訳でファイルを書いたりコマンドを実行したりする必要はないため。フラグの正確な名前は実装時に手元の版の `--help` で確かめる。
- 呼び出しはコアの外の小さな crate（`amonhen-assist`）の `Assistant` トレイトに閉じ込め、実装を CLI ごとに 1 つ置く。出力の読み取りは CLI ごとに小さく分け、版を確かめる（Codex の `exec` のイベントの形は変わりやすい）。プロセスの起動は `Platform` から注入する（SSH 先のリポジトリでも、CLI は手元で動かす）。
- 選んだ CLI が見つからない・ログインしていないときはボタンを無効にし、理由を出す。

### プロンプトの設定（Settings > AI > 詳細）

用途ごと（翻訳・コミットの解説・hunk の解説・メッセージの提案・コンフリクトの解消・コンフリクトの解説）にプロンプトを編集できる。

- 各用途に組み込みの既定のプロンプトを持ち、編集したものだけを保存する。「既定に戻す」と、既定との差分の表示がある。
- プロンプトは差し込みの変数を使うテンプレート。使える変数は用途ごとに一覧で見せ、知らない変数はエラーにする（例: `{{diff}}`・`{{message}}`・`{{files}}`・`{{language}}`・`{{base}}`・`{{ours}}`・`{{theirs}}`・`{{ours_commits}}`・`{{theirs_commits}}`・`{{path}}`・`{{recent_messages}}`）。
- 返させる形（JSON の形）はアプリが決めるもので、プロンプトの編集では変えられない。プロンプトの末尾に自動で足す。
- 「試す」ボタン: 今のリポジトリの今の選択で、編集中のプロンプトを実行し、送る内容と結果を並べて見せる（キャッシュは使わない）。
- 保存は `~/Library/Application Support/Amon Hen/prompts/<用途>.md`（手で直せる・dotfiles で持ち歩ける）。リポジトリの `.amonhen/prompts/<用途>.md` があればそちらを優先する（チームやリポジトリごとの書き方に合わせるため）。どちらを使っているかは設定画面とボタンのツールチップに出す。リポジトリのプロンプトは clone したものにも入っているので、初めて使うとき・内容が変わったときに中身を見せて確かめる（許可はリポジトリとプロンプトのハッシュで覚える）。
- キャッシュの鍵にはプロンプトの内容のハッシュも入れる（編集したら取り直す）。
- 送る前に送る内容（差分の大きさ、ファイル数）を見せ、リポジトリごとに「このリポジトリでは使わない」を選べる。既定は無効。
- 結果は流しながら表示し、コミット ID＋種類＋言語＋CLI＋モデル＋プロンプトのハッシュで永続キャッシュに入れる（2 回目は即表示）。
- 大きな差分は、ファイルの一覧と行数だけ＋見えているファイルの差分に絞って送る。

## 10. Activity（内部の動作・履歴・性能）

Window > Activity（⌥⌘A）。ツールバーのスピナーからも開く。リポジトリごとではなく、アプリ全体で 1 つ（左でリポジトリを絞り込める）。

| タブ | 内容 |
| --- | --- |
| Operations | 実行中・済みの操作。git のコマンド行、開始時刻、所要時間、終了コード、標準出力・エラー。実行中のものは進捗（fetch・clone の受信量）と取り消し。失敗したものは赤く、帯の通知からここへ飛ぶ |

- 右クリックで JSON に書き出す（不具合の報告と計測の比較用）。

## 14. Worktree

Claude Code などは worktree をしきりに作る（`.claude/worktrees/` の下など）。そのたびに別のリポジトリとして開くのは
煩わしいので、リポジトリの worktree はそのリポジトリのタブの中に置く。考え方は git の worktree に合わせる。

git の考え方と、アプリが守ること:

- worktree は対等。それぞれが作業ツリーと HEAD・index の組で、元のものは `.git` を持っているだけ。アプリは
  `git worktree list` と同じく、元のものを先頭にするほかは同じに並べる。
- ブランチ・タグ・リモート・オブジェクト・stash の一覧・設定は全部の worktree で共有。HEAD・index・作業ツリーの
  ファイル・途中の操作（rebase・merge など）は worktree ごと。
- git の命令は、実行した worktree に対して働く。アプリは**書き込む先の worktree** を 1 つ持ち（git の「今いる
  worktree」）、HEAD・index・作業ツリーに触れる命令だけをそこに向ける: checkout・commit・amend・stage・discard・
  merge・rebase・pull・reset・cherry-pick・revert・stash（退避と pop）・Undo。リポジトリ全体の命令（fetch、
  ブランチ・タグの作成・名前の変更・削除、リモート）は、どの worktree からでも同じに働く。
- 1 つのブランチは 1 つの worktree でしか checkout できない。アプリは押し通さない（`--ignore-other-worktrees` は
  使わない）: ほかの worktree が checkout しているブランチを選んだら、書き込む先をその worktree に移す。
- 「今のブランチ」は書き込む先の worktree のブランチ: Branches で太字・色付きのアイコン、History で塗った札、
  ツールバーの Branch。worktree はどこでも 3 つの印で見分ける: ✎ 書き込む先、⌂ メインの作業ツリー（`.git` を持つ
  もの）、⑂ 追加した worktree。Branches では、今のブランチに ✎、メインの作業ツリーのブランチに ⌂、追加した worktree が
  checkout しているブランチに ⑂ と緑のアイコン（worktree はツールチップに）。History は各 worktree の HEAD に同じ印の札を
  付け、追加した worktree のブランチの札は緑。ブランチの切り替えのパネルには「worktree … で使用中」。detached HEAD の
  worktree はブランチがないので、Worktrees と History にだけ出る。
- worktree の作成・削除は git で行う（`git worktree add`・`remove`・`prune`、一覧は
  `git worktree list --porcelain`）。`.git/worktrees` を直接いじらない。変更が残っている worktree の削除は確かめて
  から `--force`。ロック中のものはロック中と見せ、片付けない。フォルダがなくなったものは片付け待ちと見せる。
- ほかの worktree は、変更を数えるためだけには開かない。開いたリポジトリのエンジンが、それぞれの中で `git status`
  を動かし（8 つずつ）、1 回の要求でまとめて答える（`worktreeChanges`。SSH 先でも 1 本のつながりで全部の worktree
  を扱う）。エンジンは数を覚えておき、変わった worktree だけを数え直す: すべての worktree の HEAD と index
  （`<git dir>/worktrees` の下。ファイルが少ないので軽く、stage・コミット・checkout はどこでも 10 秒以内に分かる）を
  見張り、変更のある worktree は 30 秒ごとに数え直す。作業ツリーのファイルは見張らない（Linux の inotify はフォルダ
  ごとに 1 つ使い、カーネルのメモリを 1 つ約 1 KB。minix のような大きな作業ツリーは 1 万 7 千フォルダあり、59 個を
  見張ると上限の約 100 万に届く。少しでも数十 MB かかり、少し遅れてよい数のためには重い）。ウィンドウは前にある間
  10 秒ごとに数を頼み（何も変わっていなければ git は動かない）、5 分ごとに全部を数え直す（変更のない worktree を、
  stage せずに書き換えた分を拾う）。
  開いたままにするのは、書き込む先と、その前に書き込んだ 2 つまで。
- Undo の記録は worktree ごと（`<git dir>/amonhen/undo.json`。追加した worktree は自分の git dir を持つ）で、HEAD
  と同じ。共有のブランチを動かした操作を戻すと、どの worktree からもそう見える。

見るときは混ぜ、書くときは 1 つを名指す:

- **見る（全部の worktree をまとめて）**。サイドバーの Working Copy の下に、全部の worktree を変更の数つきで並べる（書き込む先は ✎）。押すとその worktree を
  書き込む先にして、変更を見せる。メインの作業ツリーを先に、残りは名前の順（w2 は w10 の前）。変更のない worktree は「変更なし N」に
  まとめて畳んでおき、作業中のものを目立たせる。フォルダの名前が同じ worktree は、見分けがつくところまで親のフォルダを足す（`aslr/src`・`ssp/src`）（メインの作業ツリー、書き込む先、フォルダの消えたもの、ロックしたものはいつも出す）。History では、各 worktree の HEAD のコミットに札を付ける（緑。ブランチの札の前。書き込む先は ✎、メインの作業ツリーは ⌂、
  追加した worktree は ⑂。変更のあるファイルの数つき）。どの worktree がどこにいて、どれだけ書き換えているかが 1 画面で分かる。Working Copy の右の一覧は、書き込む先の worktree の変更だけ（はじめは全部の worktree の変更をここに並べたが、worktree が多いと探しにくいので、サイドバーに移した）。
- **書く（1 つの worktree。いつも見せる）**。ツールバーに書き込む先（✎ 名前）をブランチと並べて出す。サイドバーか
  ✎ で worktree を選ぶと、それが書き込む先になる。確認のシートには worktree を書く（「gui-gtk4 に
  Pull」）。
- **ほかの場所**。リポジトリのページと一覧では、worktree を別のリポジトリとして出さず、そのリポジトリの下に出す
  （スキャンで見つかったものも）。worktree のフォルダを開いたら（CLI・Finder）、そのリポジトリのタブを、その
  worktree を書き込む先にして開く。CLI は git と同じく実行した worktree に対して働き、`amonhen worktree` は
  `git worktree` と同じ並び（list・add・remove・prune）。
- New Worktree…（ブランチかコミットから、フォルダを選んで）、Remove Worktree、Prune、Finder で表示、ターミナルで開く。

## 決めたこと

| 論点 | 決定 |
| --- | --- |
| Working Copy の一覧 | チェックボックスの 1 群（index の状態をそのまま示す。一部だけのときは ▣） |
| History の差分の既定 | 全ファイルを縦に。巨大なコミット（ファイル数 200 超など）は自動で単体のファイル表示に（案のまま進め、使ってみて見直す） |
| マージエディタの並び | Ours・Result・Theirs の 3 列だけ |
| AI の接続先 | 手元の CLI。Claude Code と Codex のどちらかを設定で明示的に選ぶ（既定は「なし」、用途ごとには分けない） |
| ショートカット | 独自の規則で決める（ほかのクライアントには合わせない） |
| Refresh | ツールバーに残す（⌘R） |
