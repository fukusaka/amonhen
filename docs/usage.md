# Usage

[日本語](ja/usage.md)

How to use the app (macOS), SSH hosts, the shared daemon and the CLI. For installation see [install.md](install.md),
and for the VSCode extension see [apps/vscode](../apps/vscode).

## App

- On launch, the repository page (Window > Repositories, ⇧⌘R; File > Open…, ⌘O, shows it too) appears. On the left are All, Favorites, Places and your groups; on the right, the repositories with sortable columns (Name, Branch, Status, Last Commit, Opened). Add (+), or the Places heading's right-click, has Add Local Repository… and Add SSH Connection…; Remove from List takes one off (the folder is left untouched). File > Quick Open… (⇧⌘O) finds a repository by name. Closing the last window leaves the app running with no window; click its Dock icon to bring back the list.
- Sidebar: Working Copy / History, branches (folders, ahead/behind upstream ↑↓, gone), remotes, tags, stashes, submodules. Right-click for checkout, merge, rebase, syncing a branch that is not checked out with its upstream (Fast-Forward when it is only behind, Push when only ahead, Publish when it has none), create, rename, delete, stash operations, and updating a submodule or opening it in a separate window. Dropping a branch onto another branch merges / rebases (no checkout if a fast-forward suffices); dropping it onto a remote pushes.
- Toolbar: Fetch, Pull, Push, Stash, Undo. Rewriting history, discarding changes, dropping stashes and the like can be reverted with Undo (the record is shared with the CLI and the VSCode extension).
- Working Copy: files are shown as a List of paths, a Tree of folders or by File Name (switch above the list). Click diff lines to select them (a hunk header selects the whole hunk, Shift selects a range, ⌘ adds to the selection), then Stage Lines / Discard Lines. The ␣ button above the diff ignores whitespace as History's does (it turns the accent color while it does); while it does, the staged and unstaged changes are shown separately and lines can't be staged or discarded. Space / Enter stages / unstages. Write a Summary and Description and commit with ⌘↩. A conflicted file opens the 3-pane merge editor below the list: Accept Current / Accept Incoming / Accept Both per conflict (and Accept Base when there is a base); Take Current File / Take Incoming File take one side for the whole file, and Mark Resolved finishes it. The view options at the right of its bar hold Wrap Long Lines.
- History: a list with a graph (subject and branch / tag labels, with author, date and ID below). Right-click to edit commits on HEAD's first-parent line (the items aren't shown for other commits): Edit Message…, Squash into Previous… and Drop… start editing on History with that change marked, and Interactive Rebase from Here… starts it from that commit (each row in the range gets a mark at the right end — pick, reword, squash, fixup, drop or edit; click it or press p, r, s, f, d or e to choose, drag rows to reorder them, drag the line under the range to take in older commits, then Apply Changes runs it all as one rebase; merges are recreated as they were); Split… stops at a commit to commit its changes in parts. The menu starts with copying the ID and names, and also has cherry-pick, revert, saving as patches (Save as Patch…; select several for a series) and creating a branch or tag. Drag a commit between rows to reorder, onto another commit to squash it into that one, or out of the window to drop it; each starts editing on History with that change marked (inside the edit, it just marks the row). The commit is carried as its row, its place is left empty, and rows it can't be dropped among are dimmed. A merge can be folded (right-click, or ← on it): its commits are hidden behind a "+N" badge, which shows them again (or →); the display menu folds or shows every merge, and the fold is kept per repository. At the top, switch between All Branches / Current Branch / a chosen ref. ⌘F searches commits (Enter / ⌘G for next, ⇧Enter / ⇧⌘G for previous; you can also show only the matching commits). On the right, the commit details stay at the top and the changed files are the file headers of one diff, all folded at first: each shows its kind in color (A, D, M, R), the path (renames as `src/{old.rs → new.rs}`) and its line counts, and opens in place when clicked. The bar above switches between Changes and All Files, shows the file count and line totals, shows the files as a list or a tree (whose folders fold), expands or folds every folder or every diff (Expand All Diffs leaves generated files such as lockfiles and `linguist-generated` files, and very large changes, folded), turns wrapping long lines on and off with the ↩︎ button beside it (also View > Wrap Long Lines, ⌥Z; GTK4: Alt+Z; for every diff), and with the ␣ button chooses the whitespace to ignore when comparing lines (at line ends, changes in its amount or all of it, as `git diff --ignore-space-at-eol`, `-b` and `-w` do; not remembered); the view options hold, under Commit Details, the Details Shown (Compact, Standard, Full), Fit Height Automatically and Show Only Commit Details (macOS: also the button at the top right of the commit details, which restores them too); under Code, Wrap Long Lines; and the AI items. Dragging the divider below the commit details keeps that height for every commit until Fit Height Automatically is chosen again. In the message, trailers link `#123` and commit IDs like the body, and a merge notes that its changes are shown against its first parent. Each file header's ⋯ (or a right-click) has Show Whole File, Open File at This Commit, Blame, File History, restoring and copying the path; the mark left of a hunk header shows 20 more lines around it. Hunk headers name the enclosing function as `git diff` does (`diff.<driver>.xfuncname` for the file's `diff=` attribute). Images (and SVG) compare side by side with their size, or by swipe, onion skin or differing pixels. All Files shows the whole tree at the commit (changed files marked, deleted ones struck through) and a file's contents at that commit, with lines added by the commit in green, changed lines in blue and a mark where lines were deleted. Images zoom (buttons, pinch, ⌘-scroll) there and in the comparisons, and a button beside the zoom switches the checkerboard behind transparent pictures between light and dark (dark by default for light pictures such as white icons, chosen anew for each file); any format macOS reads (GTK4: gdk-pixbuf) counts as an image. SVGs show as a Picture, as Text, or as Mobile: the features that break on Android VectorDrawable, iOS (CoreSVG), flutter_svg and react-native-svg, and per renderer the original beside how it looks there: Android Studio's and flutter_svg's own conversions are built in (ported, no Java or Dart), iOS and React Native are approximations. Android VectorDrawables (`.xml` files whose root is `<vector>` or `<animated-vector>`, in any folder) show as a Picture or as Text: `@color/…` references are looked up in the nearest `res` folder's `values*/` files at the same commit, theme attributes (`?attr/…`) and colors not found are drawn in the text color with a note under the picture, and an animated vector shows its still picture. Markdown shows formatted (Preview) or as Text, laid out by the app: GitHub's tables, task lists, footnotes and alerts, the HTML GitHub renders (`align` for centered logos and rows of badges, sized images, `<details>` that open and close, `<picture>` choosing the image for the appearance, tables spanning cells, `<kbd>`, `<sub>`, `<sup>`, `<ins>` and `<del>`; comments are hidden, and like GitHub, styles, scripts and forms are left out), code with syntax colors, Mermaid diagrams (drawn by a port of pele, all 34 of its kinds; others such as ZenUML stay code; Settings > Theme > Mermaid > Colors picks the syntax colors, pele's, Mermaid's default/dark by appearance, one of its named themes, or a theme imported from a mermaid-cli config file; a diagram's own `%%{init}%%` or front matter `theme`/`themeVariables` comes first; gantt dates are counted in the system time zone or the one chosen in Mermaid > Time zone), Graphviz DOT diagrams (` ```dot `, ` ```graphviz ` or ` ```gv `, where `layout` picks the engine, or a fence named after one, such as ` ```neato `; drawn by the app's own layouts, not Graphviz, so the layout differs: dot's layers, neato's stress majorization with `pos`/`pin`, `len`, `overlap` and `sep`, fdp's and sfdp's forces (fdp lays out clusters as boxes), twopi's rings, circo's circles, osage's packed clusters and patchwork's treemap; colors the diagram doesn't set follow the same Colors setting, and HTML-like tables (with gradient fills), `splines=ortho`, `samehead`/`sametail`, ColorBrewer color schemes and images are drawn; images (a node's `image`, a table's `<IMG>`) come only from the same commit, by a path relative to the Markdown file's folder; what can't be drawn — images that can't be read there, unknown shapes, color schemes and layout engines, and some layout options such as `overlap=compress` or `mode=hier` — is drawn approximately with a note under the picture), math as on GitHub (` ```math ` fences and `$$…$$` blocks, inline `$…$` and `` $`…`$ ``, found by GitHub's rules: a `$` opens math only at the start, after a space or after `(`, and the closing `$` can't be followed by a letter, digit or `_`, so `$5 and $6`, `$5/$10` and `a$x$b` stay text; italics, links and footnotes hold no math; drawn by RaTeX, a port of KaTeX, with the KaTeX fonts in the text color, keeping `\color`; inline math sits on the text's baseline; a formula that can't be drawn shows its source and why), images from the commit, and bare URLs, #123, @user and commit IDs as links; nothing is fetched. ⌘F (GTK4: Ctrl+F) finds text in the formatted Markdown with the same bar as the diffs, key caps and table cells included; pictures and closed `<details>` aren't searched. Other binary files open in Quick Look (GTK4: GNOME's previewer, or the default app). A commit with more than 200 files reads each file's diff when it's opened.
- Range Diff: right-click a local branch and choose Compare with Previous Version (or Repository > Compare with Previous Version) to compare it with its version before the last rebase, History edit or amend, as `git range-diff` does: = same, ! changed (with the diff of the two patches), < dropped, > added. Two commits selected in History or a Reflog row can be compared too.
- Patches: Repository > Apply Patch…, or dropping .patch / .diff / .mbox / .eml files on the window, shows what they change and whether they apply, then applies mail patches as commits (`git am`) or a diff to the working tree (`git apply`). When am stops at a patch, the bar under the toolbar says why, with Retry with 3-Way Merge, Continue, Skip and Abort. Both can be undone. The CLI has `amonhen format-patch`, `amonhen am` and `amonhen apply`.
- Archives: Commit > Export Archive…, or Export Archive… on a commit in History or on a branch or tag in the sidebar, writes that commit's files as a zip, tar.gz or tar file (`git archive`; `.gitattributes` decides what is left out), optionally only one folder. In the CLI, `amonhen archive`.
- Bundles: Repository > Save Repository as Bundle…, or Save as Bundle… on branches or tags in the sidebar, saves commits in one file that git can clone or fetch from (`git bundle`), all history or only what comes after a commit the receiver has. In the CLI, `amonhen bundle create`. To clone from a bundle, put the file in the Clone sheet's URL (or Choose Bundle…), or give it to `amonhen clone`. Repository > Fetch from Bundle… (or `amonhen bundle fetch`) puts a bundle's branches under a name of their own, like a remote's.
- Submodules: the sidebar marks a submodule not checked out, at another commit than the one recorded, or with changes inside. Its menu has Update (the recorded commit, as git does), Update… (also the submodules inside it, or the latest commit of the branch it follows), Edit URL…, Branch to Follow… and Remove… (the repository data in `.git/modules` is kept unless you choose to delete it); the Submodules group and the Repository menu have Add Submodule… and Update Submodules…. The Clone sheet can check out submodules too. In the CLI, `amonhen submodule` and `amonhen clone --recurse-submodules`.
- Subtrees (when this machine's git has `git subtree`): Add Subtree… in the Repository menu brings another repository's branch into a folder. The sidebar's Subtrees group then has Pull…, Push… and Split… for each, starting from the repository, branch and squash used last. In the CLI, `amonhen subtree`.
- Diffs: drag to select text and ⌘C, ⌘F to search. Syntax highlighting is applied in the background after display.
- History search syntax: words are searched in the subject, author and ID. Separate with spaces for AND, `or` for OR, and group with parentheses. `author:` `committer:` `subject:` `message:` `commit:` `path:` `contents:"..."` (e.g. `path:fs/ (author:linus or author:greg)`). `author:` and `committer:` match the name or the email, and also the name the mailmap gives; `message:` searches the whole message, body and trailers included.
- People are shown by the names and emails in the repository's mailmap (`.mailmap`, `mailmap.file`), as `git log` does; the details show the recorded name and email under them when they differ. git's `log.mailmap` turns this off; it is on Repository Settings > Author and Signing (and Settings > Git for all repositories), with the mailmap file. Changing either shows the names again without rebuilding History. Blame always uses the mailmap, as git does.
- Right-click a file (in Working Copy, or a changed file in History) for Blame and File History (renames are followed too). They open in a tab next to the repository's tab, with the same toolbar (its buttons switch back to the repository's tab and act there); drag the tab out for a separate window, and put it back with Window > Move Tab to Window ▸, which moves the front tab into the window chosen and lists the repository's window first (or drag its tab onto a tab bar; View > Show Tab Bar, ⇧⌘T, shows the tab bar of a window with one tab). Opening the same one again replaces its tab with a fresh one. Merge commits are left out unless Show Merge Commits is on (the list's context menu, or Settings > Appearance > File History). Double-click a line or commit to select it in History. File History opens at once with the newest 100 commits and adds the rest as they are read; when the file was renamed, a heading with the name it had then sits above each name's commits. Right-click a commit there for Show in History, Blame at that commit and copying the ID or path (Return shows it in History, ⌘C copies the ID).
- To bring a file back as it was, right-click it among a commit's changed files (History, Reflog) for Restore This Version… or Restore Version Before This Commit…, or a commit in File History for Restore This Version…. The working tree file is replaced (`git restore --source`; a file that version lacks is deleted, and going back before a rename brings back the old name); the sheet can stage it too, and Undo brings back the file as it was. In the CLI, `amonhen restore --source <rev> [--staged] <path>…`.
- Large repositories: when cloning, Download chooses Everything, File contents when needed (a partial clone, `--filter=blob:none`) or Recent history only (a shallow clone of 1, 100, 1,000, 10,000 or any number of commits), and Check out only some folders makes a sparse checkout. A shallow clone's History ends with a band that fetches older commits. Repository Settings > Fetching and Folders shows what the repository has and changes it: fetch more history or all file contents, choose the folders to check out, and turn git maintenance on or off. History and Working Copy in the sidebar carry a mark for such a repository.
- View > One Line per Commit makes History rows a single line. Repositories that were open when you quit are reopened on the next launch.

## Repositories on SSH hosts

Use Add SSH Connection… on the repository page and enter the host and path, or `AmonHen ssh://[user@]host[:port]/path/to/repo` (`/~/src/repo` for a path from home). You must be able to connect without a password, using a key or ssh-agent. On the SSH host, only git processing is done, by `amonhen --stdio`. If an `amonhen` of the same build is on the SSH host's `PATH`, or one of the same build was placed there earlier, it is used; otherwise the bundled engine (Linux x86_64 and aarch64, macOS arm64, Windows x86_64 and arm64) is pushed to `~/.local/share/amonhen/engine/<content hash>/` (its contents are verified after pushing; `AMONHEN_PUSH=0` disables pushing, `AMONHEN_REMOTE_ENGINE` specifies the location).

An SSH host running Windows (its OpenSSH server) works too, whatever its default shell is (cmd.exe, PowerShell or pwsh): `ssh://host/C:/src/repo` for a path on a drive, `/~/src/repo` from home. The engine is sent by scp to `%LOCALAPPDATA%\amonhen\engine\<content hash>\` and started by the default shell. Windows PowerShell, which every Windows 10 and 11 has, reads what is on the host. The login shell switch on the host's Environment Variables page doesn't apply there.

Settings > SSH Hosts holds everything about an SSH host: the hosts Amon Hen knows (those in Places, plus any you add with +), and for the selected host its connection (state, Check Connection, which engine to run there and whether to send one when none fits, the engine in use, whether commit signatures are verified with this Mac's keys or the host's, and the folders to scan, the same list as in Places) and the pages of Settings > Git for every repository on that host (read from and written to the host's `--global`, through the engine started there without a repository). Its Programs page chooses the git that runs there, kept in the host's own Amon Hen settings (see below), and its Environment Variables page shows the engine's environment and can start the engine with the environment of the host's login shell. Settings… on a host in Places and the git line under a repository's Settings list open it; Settings… on This Mac opens Settings > Git.

## Which git runs

Amon Hen runs the git chosen in Settings > Git > Programs. The choice belongs to the machine and is kept in Amon Hen's settings there, `~/.config/amonhen/settings.json` (`$XDG_CONFIG_HOME/amonhen/` when set, `%APPDATA%\amonhen\` on Windows), as `{"git": "/opt/homebrew/bin/git"}`; the CLI, the shared daemon and the VSCode extension on that machine follow it, and on an SSH host the engine, the CLI and the VSCode extension follow the file on that host, which the host's Programs page in Settings > SSH Hosts writes. Without a choice, the first `git` on the PATH runs; the VSCode extension uses VSCode's `git.path` before the PATH. `AMONHEN_GIT` in the environment overrides the file for that process. If the chosen git isn't there, what runs git stops with an error saying so, instead of running another git.

## Shared daemon

With "Open repositories through the shared daemon (SSH hosts too)" in Settings > Performance, or Open Through the Shared daemon in the repository page's context menu, a repository is opened through the local shared daemon (`daemon:/path`, `daemon:ssh://host/path`). History, the search index and SSH connections are shared with the CLI and the VSCode extension. Check its state in the Daemon tab of Window > Activity or with `amonhen daemon status`.

## CLI

`amonhen --help` lists all commands. The main ones:

```sh
amonhen .                      # open in the app
amonhen log -n 20 fix          # history with a graph (search syntax works too; --json adds recordedAuthor where the mailmap changed it)
amonhen status / diff / show   # Working Copy and commit contents (--json for the form FEs read)
amonhen stage --rows 3,5-9 f   # stage diff lines (see the numbers with amonhen diff --combined --rows)
amonhen diff -w HEAD           # ignore whitespace as git diff does (-w, -b, --ignore-space-at-eol; diff and show)
amonhen undo [--list]          # undo operations (record shared with the app and the VSCode extension)
amonhen range-diff --previous  # compare the branch with its version before the last rebase or amend (git range-diff)
amonhen log -C ssh://host/path # SSH host (the shared daemon keeps the SSH connection alive)
                               # asks before sending the engine to the host (--send-engine: without asking)
amonhen daemon status          # state of the shared daemon
```

## Terminal (TUI)

`amonhen tui [<path> | ssh://host/path | daemon:<path>]` shows the repository inside the terminal, for an SSH session or a pane beside an editor. It is in its first stages; [tui.md](tui.md) says what is built and what is not. `?` lists the keys of the focused pane, and `:` lists the commands by name. It captures the mouse unless the machine's `settings.json` says `{"tui": {"mouse": false}}`; `M` turns it off and on while it runs.

- Panes: the sidebar (from 100 columns; `0` otherwise), the main view (`1` Changes, `2` History, `3` Reflog) and, beside it or on Enter, the commit's details or the file's diff. Tab goes round them, Esc goes back, `q` quits.
- History: `j` `k` and the usual keys move, `/` searches with the History search syntax, `n` `N` go to the next and previous match; `y` cherry-picks, `v` reverts and `c` checks out the selected commit; `e` edits its message, `F` fixes it up into its parent, `X` drops it and `|` splits it (its changes go back to the working tree to commit in parts, then Continue).
- Working Copy: Space stages or unstages a file, or in the diff a line (a hunk on its header); `d` discards after asking; `B` and `L` open the file's Blame and File History; `v` starts a range of lines; `c` writes the message (`Ctrl-e` there opens git's editor), `Ctrl-s` commits and `Ctrl-p` commits and then pushes; `a` amends. On a conflicted file `o` `t` take the current or incoming side, and in its diff `o` `t` `b` resolve one conflict.
- Operations: `f` fetch, `p` pull, `P` push, `b` new branch, `s` stash, `S` pop, `u` undo, `R` reset to the selected commit. `M` turns the mouse off so the terminal can select text; `Ctrl-z` suspends. In the sidebar, on a ref: Enter selects its commit, `c` checks it out, `m` merges it, `r` rebases onto it, `n` renames a branch, `D` deletes a branch or tag; `T` anywhere makes a tag at the selected commit or ref; on a stash: `a` `o` `x` apply, pop, drop. While a merge or rebase is stopped: `C` continue, `K` skip, `A` abort.
- Passwords and passphrases that git or ssh ask for are asked on the bottom line (Unix).
